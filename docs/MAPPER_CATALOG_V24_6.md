# Equipment Mapper catalog and frequency controls

Mapper starts by asking which equipment mods the user has. Confirming with all boxes unchecked selects the base-game catalog. Unlocked, RAW Accessories and GameDay Gear add their known items. Preview reconstructs the allowed catalog from that selection and rejects unavailable items, including paired replacements. A catalog entry does not depend on anyone currently wearing it in the save.

Rules can replace a selected item or assign a catalog item to filtered players. Existing and replacement selections use readable names, category/search controls, explicit equipment slots and 100-item pages. Same-item and any-color matching, left/right pairs, color preservation and team/position/player filters remain available. Unknown or unverified catalog items are not generated.

The rule editor now follows **Equipment → Players → Review**. Choose Replace, Remove or Assign, select the equipment, choose the players, then set Frequency/Fill and review the complete rule. Remove selects the verified empty item for that slot automatically; it cannot remove required helmets, facemasks or cleats. Left/right equipment has explicit side names and retains asymmetric saved choices. Assignment hides replacement-only matching controls. The contextual picker identifies what is being selected, retains search/category choices, and returns to the draft on Cancel or Escape.

Switching from Replace/Remove to Assign carries the selected Existing Item into Item to Assign, including asymmetric left/right selections. Switching back carries the currently assigned item into Existing Item and restores the earlier replacement draft when its slot is still valid. Changing to a different equipment slot clears an incompatible replacement. These transitions retain player filters, Wearing Item and frequency settings; cancelling leaves the saved rule untouched.

Player counts and the optional specific-player list follow the same original-outfit, team, position and Wearing Item intersections as Preview. The list has search, selected-only mode and 100-player pages, retaining checked identities between pages. Counts run in the background against the current save fingerprint; complete appearance data is not sent to the renderer. Counts describe matching players before frequency and compatibility checks. Unavailable saved filters or changed player identities require an explicit correction rather than being silently discarded.

Queued rules show a readable operation, target scope and frequency, with consistent Edit, Duplicate and Remove actions. Conflicting previews link directly to the affected rules. Modal widths, footer actions and control heights follow the shared application frame, including narrow windows. Closing or cancelling a draft leaves the queued rule unchanged.

For v25.0, known new outfit incompatibilities remain in the reviewed preview, with a red warning and an **Apply Anyway** confirmation. The preview headline, warning text, border and confirmation use danger red regardless of accent color or light/dark theme. Cancel preserves the preview and writes nothing. Apply requires an explicit confirmation against the stored plan; preview options cannot pre-approve a later Apply. Invalid slots/references, malformed or shared equipment, conflicting assignments and stale saves retain their existing blockers. Existing unrelated incompatibilities are not silently repaired by Mapper; coordinate compatible assignments/removals in the same batch to avoid introducing new clashes. Patcher's Remove Specific Item(s) and Remove Handwarmers remain convenient batch-correction shortcuts, including selecting multiple items together and removing all known handwarmer variants without separate mapping rules.

Target Players includes an optional **Wearing Item** catalog condition. Select the item, optionally Include Other Colors, then choose the source item and its replacement as usual. For example, Wearing Relaxed Tee White + Include Other Colors, replace Tight Turtleneck White with No Neckwear. The condition intersects existing team/position/player filters. Only the same original on-field outfit qualifies; wearing a tee at home does not remove neckwear from an unrelated away outfit. Body tattoo conditions use the shared Base layer. Missing None slots retain normal implicit-None behavior. Frequency populations count only players with both the source and the condition; pairs count once. Queued rules match original equipment, so one rule cannot manufacture the condition for another. Old rules without a condition keep their behavior. Unavailable mod items or invalid conditions are rejected before changes are prepared.

The initial Mods You Use page now uses Quickstart's shared bordered, equal-height mod rows, version labels and help icons. Mod gating, base-game-only confirmation and saved selections are unchanged.

Frequency is a whole percentage from 0 to 100. It limits each team's matching-player population, rounding fractional limits up to whole players. With Fill to Frequency enabled, the mapper selects up to that limit. Otherwise, each matching player has the configured chance and selections stop at the limit. Sampling is stable for the same rules and input. Paired rules count each player once. If the source item is absent, the result is zero changes. Known outfit incompatibilities require confirmation before Apply; conflicting assignments still block it. Neither causes unrelated equipment to be silently removed.

Catalog replacements preserve existing element metadata and use only the specified slot. Verified body tattoos use the native Base appearance category. Other gear uses PlayerOnField loadouts. Brand, helmet/facemask and equipment compatibility checks produce confirmable warnings; shared-row, stale-preview, slot/reference and storage checks retain their existing safety behavior. Preview does not modify the save. Apply writes the reviewed, backed-up, verified plan.

New catalog IDs are stable across saves. Old Mapper presets using opaque saved-item configuration IDs require selecting their items again. The mapper reports these unavailable rules instead of guessing which catalog item they meant. Existing catalog presets retain exact matching, single-side or asymmetric pairing, custom metadata and legacy replacement-cap semantics when saved without a frequency change. New UI rules use Frequency and Fill to Frequency.

Validation covers mod gating and ownership filtering, items absent from a save, empty slots, frequency/chance/Fill/0%, per-team sampling, metadata and native Base handling, source immutability, real-save scoped Preview/Apply/reopen and exact unrelated-table preservation. Actual packaged UI testing chooses mods and both items, sets Frequency/Fill, filters a player and runs a real native preview.
